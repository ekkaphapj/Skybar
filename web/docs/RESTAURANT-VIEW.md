# มุมมองร้านจำลองสำหรับ PC

บนหน้าจอกว้างตั้งแต่ 1050 พิกเซล หน้าแรกใช้ฉากร้านการ์ตูนแบบ isometric อิงผัง Skybarseatplan1: โต๊ะ 1–11, ที่นั่งบาร์ B1–B8 และส่วนโต๊ะเสริม
วาดด้วย SVG ภายในโปรเจกต์ ไม่โหลดโมเดลหรือรูปจากบริการภายนอก

- คลิกโต๊ะเพื่อดูสถานะ ยอดเงิน และรายการอาหารด้านข้าง
- โต๊ะว่าง: กดเปิดการขายโต๊ะนี้ ฟอร์มจะเลือกหมายเลขโต๊ะให้อัตโนมัติ
- โต๊ะที่กำลังขาย: กดดูรายการ / รับออร์เดอร์ เพื่อเพิ่มรายการหรือเช็คบิล
- หน้ารับออร์เดอร์บน PC มีการ์ดสินค้า ค้นหาและกรองประเภทได้ กดครั้งละ 1 รายการ
- สแกนบาร์โค้ดและเพิ่มส่วนลดผ่านตัวเลือกเดิมได้ด้านล่าง
- ปุ่มมุมมองรายการสลับกลับหน้าเดิม และจำตัวเลือกไว้บนเบราว์เซอร์เครื่องนั้น
- มือถือยังแสดงหน้าจอแบบเดิมสำหรับการสัมผัส

ตัวเลขยอดขายวันนี้ จำนวนบิล กราฟทุก 2 ชั่วโมง และเมนูขายดีอ่านจาก Sell ของวันที่ธุรกิจ Bangkok (ตัดวันที่ 02:00)
โต๊ะที่เปิด ยอดรอเช็คบิล และรายการสั่งอ่านจาก TableOrders ไม่เอาออร์เดอร์ที่ยังไม่เช็คบิลไปรวมเป็นยอดขาย
สรุปยอดรวมทุกโต๊ะ/ร้านตามโครงสร้างข้อมูลเดิม ตัวเลือกร้านใช้กำหนดร้านตอนเปิดโต๊ะใหม่
ข้อมูลรีเฟรชทุก 15 วินาทีและกดรีเฟรชเองได้ ฉากอ้างอิงตำแหน่งจาก seat plan และบรรยากาศดาดฟ้า/ราว/ไฟกลางคืนจากภาพจริงของเจ้าของร้าน

ทดสอบอัตโนมัติผ่าน 275 ข้อ: logic16 frontend37 receipt14 agent15 API71 regression17 orders28 auth49 restaurant17 dashboard11

## ผังตามภาพอ้างอิง

- โต๊ะ 1–4 เรียงหน้าบริเวณหลังคารูปตัว L, โต๊ะ 5 อยู่ตรงกลาง
- โต๊ะ 6–8 เป็นโต๊ะวงรีสี่ที่นั่งทางขวา โต๊ะ 9–10 เป็นโต๊ะสี่เหลี่ยมสี่ที่นั่งด้านหลัง และโต๊ะ 11 เป็นโต๊ะกลม
- ที่นั่งบาร์ B1–B8 เรียงหน้าเคาน์เตอร์ ใช้รหัสออร์เดอร์ภายในเดิม 12–19 โดยแสดงชื่อบาร์ในผัง หน้ารับออร์เดอร์ ประวัติ และใบเสร็จ ฐานข้อมูลไม่ต้องย้ายรหัส
- ผังหลักมี 19 จุด ระบบเดิมรองรับ 20 จุด จึงแสดงรหัส 20 เป็น **โต๊ะเสริม 20** แยกด้านล่าง ไม่แทรกลงในตำแหน่งจริง
- ตัววาดรองรับโต๊ะเสริมที่ได้รับเพิ่มเติมจากข้อมูล โดยไม่ตัดทิ้งเมื่อเกินจำนวนในผัง ความสามารถเปิดโต๊ะใหม่ยังใช้ข้อกำหนดของ API และฐานข้อมูลเดิม
- ทดสอบผังและการคลิกที่ความกว้าง 1050, 1280, 1440, 1920 และรายการบนมือถือ 390 พิกเซล

## เต็มจอและลูกค้าการ์ตูน

- กด **เต็มจอ** บนภาพร้านเพื่อขยายภาพเต็มหน้าจอ พร้อมกรอบลูกค้าวันนี้ (โต๊ะ), ลูกค้าในร้านตอนนี้ (โต๊ะ), รายรับวันนี้ และรายจ่ายวันนี้ กดปุ่มออกหรือ Esc เพื่อออก เบราว์เซอร์ที่ไม่รองรับ native fullscreen ใช้พื้นที่เต็มหน้าต่างแทน
- ลูกค้าวันนี้นับรอบเปิดโต๊ะ รวมรอบที่ปิดแล้วและที่ยังเปิดอยู่ โดยใช้วันธุรกิจ Bangkok ที่เปลี่ยนเวลา 02:00 น. ไม่ใช่จำนวนเลขโต๊ะแบบไม่ซ้ำ ลูกค้าในร้านตอนนี้นับเฉพาะโต๊ะเปิด รายรับ/รายจ่ายอ่านจาก Account รวมทุกช่องทาง
- คลิกโต๊ะว่างแล้วกรอบเปิดการขายจะเลือกโต๊ะนั้นให้ มีจำนวนลูกค้า 1–5 คนและชื่อ เมื่อตกลงในฉากร้านยังอยู่ที่ฉากเพื่อดูคนเดินเข้า ส่วนการเปิดจากเมนูปกติยังไปหน้ารับออร์เดอร์
- คลิกโต๊ะที่มีลูกค้าเพื่อเปิดกรอบบิลปัจจุบัน แสดงชื่อ จำนวนคน รายการ ยอดของโต๊ะ และปุ่ม **ดูบิล** ไปยังบิลของโต๊ะนั้น
- จำนวนคนเก็บใน TableOrders.GuestCount (migration 0005) ค่าเริ่มต้น 1 สำหรับออร์เดอร์และไฟล์สำรองเดิม เก็บต่อในประวัติและข้อมูลใบเสร็จ
- ลูกค้าเดินจากทางเข้ามานั่งตามจำนวนคนและยกแก้วดื่ม เมื่อโต๊ะออกจากรายการเปิดหลังเช็คบิลจะแสดงคนเดินออก การรีเฟรชปกติไม่เล่นเดินเข้าซ้ำ และเครื่องที่ตั้งค่าลดการเคลื่อนไหวจะแสดงภาพนิ่ง
